# 执行阶段硬性要求（支持随时切换）

## 1. 阶段定义

- **A 阶段：口径与基线**
- **B 阶段：小规模实验**
- **C 阶段：归因与放大**

## 2. 每个阶段的硬性产物（必须具备）

### A 阶段（口径与基线）

必须完成：

1. 指标口径文档（CTR/CR/ROI 等）
2. 基线数据快照（至少 1 个类目）
3. 当周目标与风险清单

### B 阶段（小规模实验）

必须完成：

1. 实验卡片（目标、变量、样本、时长）
2. 实验执行记录（每天更新）
3. 阶段结论（有效/无效/待验证）

### C 阶段（归因与放大）

必须完成：

1. 归因复盘报告（结果、原因、证据）
2. 放大方案（预算、人力、频次）
3. SOP 更新记录

## 3. 随时切换阶段的规则（核心）

为保证你可以随时切换阶段，采用“**状态机** + **最小门槛**”机制。

### 3.1 状态文件

维护一个阶段状态文件：`docs/STAGE_STATUS.md`，只记录：

- 当前阶段（A/B/C）
- 切换时间
- 切换原因
- 下一检查点

### 3.2 切换最小门槛

- 从任意阶段切到任意阶段时，必须先补齐“目标阶段”的**最小输入**：
  - A：有可用历史数据样本
  - B：有明确实验目标与变量
  - C：有可复核的数据结果

> 只要满足最小输入，就允许立即切换；其余产物可以在切换后 24 小时内补齐。

### 3.3 24 小时补齐机制

切换后若缺失硬性产物，必须在 24 小时内补齐并记录在 `docs/STAGE_STATUS.md`。

## 4. 快速切换操作清单（可直接执行）

1. 更新 `docs/STAGE_STATUS.md`：写明“切换到 X 阶段 + 原因”。
2. 确认目标阶段最小输入已满足。
3. 建立该阶段任务清单（不超过 3 个当日任务）。
4. 在 24 小时内补齐该阶段硬性产物。

## 5. 判定标准（防止阶段混乱）

- **阶段正确**：当前所有任务都服务于同一阶段主目标。
- **可回退**：任意时刻都能回到 A/B/C 任一阶段并继续执行。
- **可审计**：每次切换都有时间戳、原因、缺口和补齐结果。
